# 06-02 · 配额与成本

> 一句话：**控制面为主的演练在免费额度内是够的；文件传输是第一个撞线的。**
> 所有数字来源见 [01-research/01-cloudflare-platform-limits](../01-research/01-cloudflare-platform-limits.md)。

---

## 1. 免费额度速查

| 资源 | 免费额度 | 我们的典型用量（100 会话/24h） | 余量 |
|---|---|---|---|
| Workers 请求 | 100,000 / 天 | < 1,000（WS 为主） | 99% |
| Workers CPU | 10 ms / 请求 | 0.5–3 ms | 紧但够 |
| DO 请求 | 100,000 / 天 | ≈ 7,200（心跳按 20:1 折算） | 93% |
| DO duration | 13,000 GB-s / 天 | ≈ 768 GB-s（有 hibernation） | 94% |
| D1 行读 | 5,000,000 / 天 | ≈ 20,000 | 99% |
| D1 行写 | 100,000 / 天 | ≈ 2,400 | 97% |
| D1 存储 | 500 MB / 库 | 几 MB ~ 几十 MB | 充裕（大结果必须外置） |
| KV 写 | 1,000 / 天 | ≈ 110（只放令牌/配置） | 89% |
| R2 存储 | **10 GB-month** | 500 次 × 10 MB ≈ 5 GB；**× 50 MB ≈ 25 GB** | ⚠️ **先撞这条** |
| R2 Class A | 1,000,000 / 月 | ≈ 7,500 | 99% |
| R2 Class B | 10,000,000 / 月 | ≈ 2,000 | 99% |
| Queues | 10,000 操作 / 天 | 可选，≈ 3,000 | 一般 |

复算方式：控制台 `/quota` 页与 `packages/shared/src/limits.ts#estimateUsage`。

## 2. 什么时候会撞线（按发生概率排序）

| 排名 | 触发条件 | 症状 | 处置 |
|---|---|---|---|
| 1 | **R2 存了 25 GB+ 的文件/结果** | 写入开始失败 / 账单出现 | 开 TTL 清理、压缩、只传需要的文件 |
| 2 | **用轮询心跳**（30 s） | 下午开始 1027 | 换 WS；HTTP 兜底间隔 ≥ 300 s |
| 3 | **DO 没走 hibernation**（用了 `accept()`） | duration 秒光，DO 报限流 | 必须 `acceptWebSocket()` + 自动应答 |
| 4 | **批量下发过猛**（一次 200 台 × 5 任务） | D1 行写吃紧 | 单批 ≤ 100，或分时段 |
| 5 | **每次心跳写 KV** | KV 写 1,000/天 撑不过 1,000 次心跳 | KV 只放令牌/配置 |
| 6 | **每帧一次 D1 写** | D1 写满 → 任务状态不更新 | DO 内存攒批，关闭时才落库 |
| 7 | **屏幕流 2 fps 持续** | DO 请求暴涨 + R2 存储涨 | 降到 1 fps 或只截图 |

## 3. 什么时候该上 Workers Paid（$5/月）

| 需求 | 免费 | Paid |
|---|---|---|
| CPU 超过 10 ms（例如口令登录、服务端压缩） | ❌ | ✅ 30 s 起 |
| 每天 > 100k 请求 | ❌ | ✅ 无限 |
| D1 单库 > 500 MB | ❌ | ✅ 10 GB |
| R2 存储 > 10 GB-month | 💰 按量（$0.015/GB-month） | 同上（R2 没有"付费套餐"，就是按量） |
| 需要更多 Cron（> 5） | ❌ | ✅ 250 |

**建议**：先用免费跑通；只在你确实需要"口令登录"或"每天 > 100k 请求"时再升级。
`AUTH_MODE=access` + WS 通道下，免费额度能支撑一个 100 台规模的中型演练。

## 4. 成本控制开关

| 开关 | 位置 | 效果 |
|---|---|---|
| `RETAIN_DAYS_RESULTS` / `_FILES` / `_SCREENS` | Cron 任务（`workers/console` 的 scheduled） | 到点删 R2 对象 + D1 行 |
| `next`（服务端建议间隔） | `/v1/beacon` 响应 | 额度紧张时自动拉长到 900 s |
| `META_MODE=sealed` | `wrangler.jsonc` | 减少 D1 写入字段（主机信息不落库） |
| `EDGE_DECOY` | `wrangler.jsonc` | 降低扫描器探测带来的无用请求 |
| 关闭 Queues | 不绑定 `JOBS` | 少 3,000 操作/天 |

## 5. 观测

- **实时**：`npx wrangler tail stc2-edge --format pretty`（看 4xx/5xx 与耗时）。
- **日粒度**：Cron 每天 00:10 UTC 写一行 `quota_daily`（Workers/D1/R2 用量从 CF Analytics API 拉，取不到就记 `null` 并在 UI 标"未采集"）。
- **告警阈值**：`/quota` 页 > 80% 橙色、> 95% 红色；红色时控制台顶部显示 `quota_crit` 角标（v0.2）。

> 注意：免费计划没有 Logpush；长期留存日志要自己在 Worker 里落 D1（会吃行写额度）。
