# ADR-0004：用 P-256 而不是 X25519

- 状态：已接受（2026-11）
- 影响面：`packages/shared/src/crypto.ts`、客户端实现

## 背景

现代协议（Noise、WireGuard、Signal）普遍用 X25519。我们却选了 NIST P-256。

## 决定

ECDH 用 **P-256**（`namedCurve: 'P-256'`），HKDF-SHA256 派生，AES-256-GCM 加密。

## 理由

| 端 | P-256 | X25519 |
|---|---|---|
| 浏览器 WebCrypto | 稳定支持（所有现代浏览器） | 支持度随版本/策略变化（Chrome 较新才有，Safari/Firefox 不一致） |
| Cloudflare Workers WebCrypto | 文档明确 | 随兼容性日期变化，**不能作为地基** |
| Go | `crypto/ecdh.P256()` | `crypto/ecdh.X25519()`（都有） |
| .NET | `ECDiffieHellman nistP256` | .NET 5+ 有，但生态不如 P-256 普遍 |
| C（OpenSSL） | 普遍 | 需要 1.1+ |

我们的目标是"**任何语言都能在 30 分钟内实现**"，可移植性优先于 30% 的性能差异。

## 代价

| 代价 | 说明 |
|---|---|
| 公钥 65 字节（vs 32） | 注册包里多 33 字节，无感 |
| 计算略慢 | 每次会话一次 ECDH，微秒级，无感 |
| 不是"现代审美" | 文档里必须解释为什么（就是这份 ADR） |

## 什么情况下推翻

- 浏览器与 Workers 同时对 X25519 稳定支持（届时写 ADR-0007，协议版本升 `v=2`，双写期 ≥ 1 个大版本）；
- 需要与既有 X25519 体系互操作（本项目不做互通，所以不成立）。
