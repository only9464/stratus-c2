# ADR-0003：端到端加密，服务端零知识

- 状态：已接受（2026-11）
- 影响面：协议、UI、数据模型、可用性

## 背景

C2 的控制面天生敏感。托管在 Cloudflare 上意味着：平台方、账号被盗者、内部人都可能读到存储与内存。
传统 C2（含 VShell）把密钥放在服务端，等于把内容交给运维方。

## 决定

L2（任务与结果）由**操作员浏览器**加密、**植入体**解密，反之亦然：

- 操作员私钥：浏览器 IndexedDB 里的 `CryptoKey`（不可导出）；
- 植入体：每次启动生成 ephemeral P-256 密钥；
- 服务端只见 `{tid, rid, n, ct}`，不解密、不搜索、不统计内容。

## 代价（必须接受）

| 代价 | 具体表现 | 缓解 |
|---|---|---|
| 服务端不能搜索/过滤命令 | 只能按"粗分类 + 大小 + 时间"筛 | `tasks.cat` 保留粗分类（有意的元数据泄露） |
| 服务端不能聚合结果 | "所有主机的 whoami 汇总"只能在浏览器做 | 前端批量解密（v0.2） |
| 私钥丢 = 数据永久不可读 | 清浏览器数据就没了 | 引导做加密备份（v0.3）；`viewer` 角色不发私钥 |
| 无法服务端压缩/转码 | 大结果只能原样存 | 结果外置到 R2 + 前端流式解密 |
| 审计看不到命令 | 审计只能记"谁/何时/哪个会话/多大" | 这是**有意为之**，写进威胁模型 |

## 什么情况下推翻

**不建议推翻。** 唯一合理的例外是"单人自用、追求极致方便"：提供 `AUTH_MODE=token` + 关闭 E2E 的
配置项（v0.2，默认关闭，UI 上明确标红"服务端可解密"）。即便如此，也应该是**显式开启**而不是默认。
