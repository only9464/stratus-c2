# 02 · VShell 功能矩阵与「纯 Cloudflare」可行性映射

> 调研对象：**VShell**（`github.com/veo/vshell`，Go 写的国产 C2，早期开源、后续闭源），以及社区里对标它的复刻/衍生实现（本地已有的 Rshell、ToShell 两个仓库）。
> 本文只做两件事：① 把它的功能面列全；② **逐项判定"在只用 Cloudflare 免费服务"时能不能做**。
> 许可证边界：VShell 现已闭源、原仓库无授权许可；本文档**只吸收设计思想**，不复制其代码、前端资源、协议常量或线格式。参见 [docs/README](../README.md) 与根目录 `THIRD-PARTY-NOTICES.md`。

---

## 1. 一句话定位

VShell 是"**一个进程里塞进全部协议面 + 一套运营型控制台**"的 C2：服务端同时开 HTTP/HTTPS/WebSocket/CDN-WebSocket/DNS/KCP 多个 listener，每个 listener 有自己的 `vkey`（客户端标识）与 `salt`（帧加密盐），植入体按 `mode` 选通道回连，控制台提供会话、终端、文件、屏幕、隧道、插件、笔记、多用户这几块。

它真正值得学的不是"功能数量"，而是三件事：

1. **通道落点收敛成注册表**（加一个协议 = 加一个 handler 注册，不是改 20 处）；
2. **载荷"请求时生成"**（每种形态一个投递端点，带 `Public` / `Expires` 标记）；
3. **隧道/反代主机是一等持久化资源**（有健康检查、并发上限、流量统计）。

这三件事恰好是"搬到 Cloudflare 上"时最需要重新想一遍的地方。

## 2. 功能矩阵（核心表）

判定口径：**✅ 可行** = 纯 CF 免费服务能做出等价能力；**🟡 部分可行** = 能做但要改形态/砍能力/加操作员侧客户端；**❌ 不可行** = 平台层面做不到。

### 2.1 会话与客户端管理

| 功能 | VShell 里的表现 | CF 可行性 | 原因 | CF 侧替代 |
|---|---|---|---|---|
| 会话列表（在线/离线） | 客户端表 + 心跳 | ✅ | D1 存元数据 + DO 存活性 | `sessions` 表 + `SessionDO` |
| 分组 / 标签 / 备注 | 客户端带 group/remark | ✅ | 纯数据 | D1 字段 + 前端分组 |
| 多选 / 批量下发 | 有批量删除 | ✅ | D1 `batch()` | `POST /v1/tasks:bulk`（限 100 条/批） |
| 上下线实时推送 | 服务端 WS 广播 | ✅ | DO 广播给 operator WS | `HubDO` 扇出 |
| 会话迁移/接管 | 客户端迁移（换 listener） | 🟡 | 需要客户端重新握手 | 下发 `reconnect` 任务 + DO 状态迁移 |
| 每会话连接数/流量上限 | `MaxConn`/`RateLimit`/`Flow` | ✅ | DO 单线程天然可计数 | DO 内存计数 + D1 累计 |
| 会话能力位（capabilities） | 由 agent 上报 | ✅ | 纯数据 | `sessions.caps` JSON |

### 2.2 监听器与协议

| 通道 | VShell | CF 可行性 | 说明 |
|---|---|---|---|
| HTTP / HTTPS | ✅ | ✅ | gateway worker 的 `POST /v1/beacon` |
| WebSocket / CDN-WS | ✅ | ✅ | **主通道**：gateway → DO（hibernation） |
| DNS / DoH | ✅ | 🟡 | 只能"借" Cloudflare DNS：console 用 API 写 TXT，implant 用 DoH 读；带宽极低，只做兜底 |
| TCP（裸） | ✅ | ❌ | Worker 不能监听 TCP |
| UDP / KCP / QUIC | ✅ | ❌ | 运行时无 UDP |
| MQTT | ✅ | ❌ | 需要 broker（= 自建服务器） |
| OSS / S3 作为通道 | ✅ | 🟡 | 可以用 **R2** 当"死信箱"（implant 直接读写 R2 需要凭据，等于把凭据发给植入体 → 不推荐；只做"结果落地"） |
| SSH 通道 | ✅ | ❌ | 无入站 TCP |
| 域前置（Domain Fronting） | 支持（靠 CDN） | 🟡 | Cloudflare 不允许对自家域名做域前置；只能"同域不同路径"或"多域名轮换" |
| 多 listener 并存 | ✅ | ✅ | 两个 Worker（gateway/console）+ 多个自定义域 |
| 运行期按 mode 装配端点 | ✅ | ✅ | Hono 路由注册表 + 环境变量控制 |

### 2.3 交互能力

| 功能 | CF 可行性 | 说明 / 代价 |
|---|---|---|
| 交互式 shell（PTY） | ✅ | WS 双向帧；必须合批（见配额文档），Windows 上用 `cmd /Q`，Linux 上用 `pty` |
| 单条命令执行 | ✅ | 任务模型 |
| 文件管理（列/传/删/改/预览） | ✅ | 元数据 D1 + 内容 R2，4 MiB 分片 |
| 断点续传 | ✅ | 分片清单存 D1，`offset` 语义 |
| 进程列表 / 结束进程 | ✅ | 纯任务 |
| 注册表 / 服务 / 计划任务 | ✅ | 纯任务（Windows 植入体实现） |
| 屏幕截图 | ✅ | 单帧走 R2，控制面只发引用 |
| 实时屏幕流 | 🟡 | 1–2 fps + JPEG 压缩 + R2；DO 请求额度是天花板 |
| 键鼠控制 | 🟡 | 指令帧很小，可行；但延迟受心跳/合批影响 |
| 剪贴板读写 | ✅ | 小载荷 |
| 音频 | ❌ | 带宽与 DO 额度都不允许 |

### 2.4 内网与隧道

| 功能 | CF 可行性 | 关键约束 |
|---|---|---|
| SOCKS5 代理 | 🟡 | **代理端必须跑在植入体上**（Worker 连不到私有地址）；操作员本机跑 `stc2 proxy` 客户端，把 SOCKS5 转成 WS 帧 |
| 端口转发（本地→远端） | 🟡 | 同上，应用层封装 |
| 反向隧道（远端端口→本地） | ❌ | 植入体侧无法被 Worker 主动连入；除非植入体自己监听端口（那就不需要隧道） |
| 多级跳板 / mesh 中继 | 🟡 | 只能"应用层多跳"：A 会话把帧转给 B 会话；每跳都吃 DO 请求 |
| 隧道健康检查 | ✅ | DO alarm 或 Cron（TCP 探测只能由植入体做） |
| 隧道持久化 | ✅ | D1 表 + DO 状态，重连自动重建 |
| 内网资产扫描 | ✅ | 由植入体下发扫描任务，结果回传（不做在云端） |

### 2.5 载荷与投递

| 功能 | VShell | CF 可行性 | 说明 |
|---|---|---|---|
| 服务端编译载荷 | ✅（服务端有 Go 工具链） | ❌ | Workers 无子进程/工具链 |
| 运行期生成配置并注入 | ✅ | ✅ | 生成 `config.bin` / JSON，操作员**本地编译**，或把配置作为独立文件随载荷落地 |
| 多形态（exe/dll/shellcode/raw） | ✅ | ✅ | 由操作员本地构建；服务端只负责"托管 + 一次性下载链接" |
| 载荷存储 | 落盘 | ✅ | R2 + 一次性令牌（KV） |
| 载荷过期/一次性 | ✅ | ✅ | KV TTL + D1 `payloads.expires_at` |
| 内存加载 / BOF / 插件 | 🟡 | ✅（能力在客户端，不在服务端） | 服务端只下发模块字节，模块编译在本地 |
| 代码签名 / 免杀 | ✅（部分） | ✅（本地） | 不在云端做 |

### 2.6 隐蔽与流量

| 功能 | CF 可行性 | 说明 |
|---|---|---|
| 自定义 Header / UA / 路径 | ✅ | 配置下发给植入体 |
| 心跳 + 抖动 | ✅ | 客户端实现；服务端只记录 |
| TLS 指纹（uTLS/JA3） | ✅（客户端） | 客户端库决定，与服务端无关 |
| 每会话独立密钥 | ✅ | **本项目的基础设计**（见 crypto 文档） |
| 帧级 AEAD | ✅ | AES-256-GCM |
| 服务端零知识（E2E） | ✅ | 操作员公钥在载荷里，私钥在浏览器/CLI |
| 流量伪装成正常 API | 🟡 | 受 Cloudflare 自身 WAF/JS 挑战影响；需在 zone 里放行路径 |
| 域前置 | ❌ | CF 明确禁止对自家域做前置 |

### 2.7 运营面

| 功能 | CF 可行性 | 说明 |
|---|---|---|
| 多用户 + RBAC | ✅ | D1 `operators` + 角色 → 路由元数据；用 Cloudflare Access 做前置 |
| 审计日志 | ✅ | D1 `audit_log`，写前算好、批量落 |
| Webhook 通知 | ✅ | `fetch()` 出站（注意 6 连接限制） |
| 系统资源面板 | 🟡 | Worker 侧无"服务器资源"概念，改成"配额水位"面板 |
| AI 助手 | 🟡 | Workers 可调外部模型 API，但每请求 CPU 10 ms 限制要求流式转发 |
| 对外开放 API / MCP | ✅ | console worker 的 REST + `@hono/zod-openapi` |
| 笔记 | ✅ | D1 + Markdown |
| 团队协作（多人同看一个 shell） | ✅ | DO 广播 |

## 3. VShell 的协议与帧（能确认的部分）

> 只写能从公开资料与本地分析文档确认的；其余标"未公开"。

| 项目 | 事实 | 可信度 |
|---|---|---|
| 通信模型 | **拉取式**：`/api/checkin` → 轮询 `/api/tasks` → `/api/result` 回传 | 高（本地分析文档有文件行号） |
| 加密 | 每 listener 一个 `salt`，密钥 = `hex(md5(salt))` 直接当 AES-256 key；checkin/result **可退化为明文 JSON** | 高 |
| 客户端标识 | `vkey`（`VerifyKey`）是**标识**不是密钥，比较用 `==`（非常量时间） | 高 |
| KCP 通道 | 块加密密钥 = `salt + verifyKey` 截断补 NUL 到 32 字节；默认值字面量 `"default"` | 高 |
| 任务模型 | 单表 `tasks`，`pending → dispatched` 原子领取；另有按 md5 口令反查任务 | 高 |
| 帧码表 | 一组十六进制帧类型常量（具体值不在本文引用，属于其线格式） | 高（值略） |
| 载荷注入 | 预编译模板 + 定长占位符 `ldflags -X` 注入 + gzip/XOR | 高 |
| 插件 | `./plugins` 按扩展名选平台/架构，hex 展开随命令下发；**agent 端未实现** | 高 |
| 权限 | 3 角色 + **路径前缀白名单** + JWT `role_id` | 高 |
| 隧道 | `Tunnel{ClientID,Port,Mode,Target,...}` + `Host{TargetStr,Scheme,Flow,Health}`，30 s 健康检查（tcp/http/icmp，并发 20） | 高 |
| 存储 | SQLite（Web）+ JSON（引擎）双写 | 高 |

**它的设计缺陷（我们不重复）**：明文回退、密钥走 query string、`md5(salt)` 当密钥、无前向安全、无每会话密钥、fail-open 的 license 校验、路径前缀式授权、双存储一致性。

## 4. 从 VShell 能力反推：在 Cloudflare 上必然要改的 12 条

| # | VShell 怎么做 | CF 上必须怎么做 | 代价 |
|---|---|---|---|
| 1 | 服务端开 TCP/UDP listener | 只保留 HTTPS/WSS **入站**；通道 = "客户端连出" | 丢 TCP/UDP/KCP/MQTT/SSH 通道 |
| 2 | 服务端进程常驻，内存里存会话 | 无常驻进程 → **每会话一个 DO**，状态进 DO SQLite + D1 | 要处理 DO 驱逐/唤醒，状态必须可序列化 |
| 3 | 心跳写内存，随便高频 | 心跳 = DO 请求（20:1 计费）；**必须 WS + hibernation** | 心跳间隔下限受配额约束（60 s 起步） |
| 4 | 任务队列在内存 + 单表原子领取 | D1 单写者 + 50 查询/调用 → 用 `batch()`，任务领取用条件 UPDATE | 批量下发要限条数 |
| 5 | 文件直接落本地磁盘 | R2 分片 + D1 分片清单 | 4 MiB 分片、断点续传要自己写 |
| 6 | 屏幕流直接广播二进制 | 帧落 R2，控制面只发引用；1–2 fps | 实时性下降，要显式告诉操作员 |
| 7 | 隧道在服务端建监听 | Worker 无法连内网 → **代理端在植入体**，操作员本机跑客户端 | 多一个本地组件（`stc2 proxy`） |
| 8 | 服务端编译载荷 | **本地编译**，服务端只发配置 + 托管产物 | 操作员需要工具链 |
| 9 | 配置存 YAML 文件 | `wrangler secret` + D1 `settings` + KV 缓存 | 配置变更要版本化 |
| 10 | 多用户靠 JWT + 路径白名单 | Cloudflare Access 前置 + D1 角色 + **路由元数据**授权 | 要写中间件，不能靠前缀 |
| 11 | 日志落本地文件 | Logpush/Workers Logs（保留期短）+ D1 审计表 | 审计要自己设计写入节奏 |
| 12 | DNS 通道自建权威 DNS | 借 Cloudflare DNS API 写 TXT + 公共 DoH 读 | 带宽极低、有 API 速率限制、延迟高 |

## 5. 设计借鉴清单（抄思想，不抄代码）

### 5.1 要吸收的（8 条）

1. **通道注册表**：加通道 = 加一个 adapter + 一个能力标志，路由从注册表挂载（fail-closed：未知 mode 直接 404）。
2. **载荷"链接即形态"**：`/d/:token` 一次性/带过期地交付产物，产物不落在"可枚举目录"里。
3. **隧道/代理实体化**：独立表 + 健康状态 + 并发上限，而不是会话的一个属性。
4. **每会话连接数/流量上限**：在 DO 里做计数，超限回明确错误码（不是静默丢）。
5. **统一列表契约**：`page/page_size/sort/order/q` + `{total, items}`，前端表格一套复用。
6. **批量操作逐项返回**：一条批量请求 → 每项 `ok/err`，不整体回滚。
7. **能力位驱动 UI**：载荷上报 `caps`，没编进载荷的标签页不渲染（避免"点了没反应"的假面板）。
8. **结果外置成句柄**：大结果不塞进响应，落 R2 返回 `handle`，前端分页回读。

### 5.2 明确不做的（6 条）

1. 与 VShell **协议互通/接管其会话**（无授权，且会把错误码体系绑死）。
2. 明文/弱加密回退、密钥进 URL、`md5(salt)` 派生。
3. 双存储（SQLite + JSON）。
4. 路径前缀式授权。
5. 服务端内置私钥做 license 门控。
6. 域前置（Cloudflare 不允许，且踩 ToS）。

## 6. 结论：这个框架要"像 VShell 的地方"和"必须不像的地方"

**像**：功能面（会话/终端/文件/隧道/载荷/多用户/审计）、操作手感（列表 → 详情 → Tab）、通道抽象方式（注册表）、载荷交付方式（一次性链接）。

**不像**：
- 通信模型从"轮询"变成"**WS 优先 + hibernation**"；
- 加密从"per-listener 盐"变成"**per-session ECDH + 服务端零知识**"；
- 部署形态从"一个二进制"变成"**两个 Worker + 一套 Cloudflare 存储**"；
- 内网能力从"服务端建隧道"变成"**植入体做代理 + 操作员本地客户端**"；
- 构建从"服务端编译"变成"**本地编译 + 云端只发配置**"。

这五条差异，就是 [02-architecture](../02-architecture/01-system-architecture.md) 要解决的问题清单。
